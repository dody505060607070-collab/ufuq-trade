## Architecture rules
- Remote assistant access uses OAuth-only read-only MCP tools with caller ownership filters and existing approval/RLS checks; never expose credentials or trading mutations. Why: assistant access must not widen account permissions.
- Browser assistant tools register in their owning visible screen with fail-open telemetry and no credentials. Why: the user's active view defines their scope.
- New trading settings share DEFAULT_TRADE_LOT; existing users are changed only through their authenticated settings. Why: avoid changing other users' trading risk.
- Backend is Lovable Cloud; every user-owned table is protected by RLS scoped to auth.uid(), admin access goes through public.has_role(). Why: browser writes directly to the DB.
- Roles live only in public.user_roles; the signup trigger grants admin to the first user when no admin exists. Why: bootstraps the owner without hardcoded emails.
- The MT5 EA (public/ea/ArrissaEA.mq5) talks only to POST /api/public/ea/sync, authenticated by X-Username + X-API-Key (user-level key in ea_credentials; unknown logins are auto-registered) or the legacy per-account X-EA-Key; `?format=text` returns pipe-separated command lines for MQL5. Dashboard actions insert rows into trade_commands (queued → sent → done/failed). Why: the web app never holds broker credentials and MQL5 has no JSON parser.
- Hedge plans are converted into open_trade commands inside the EA sync handler (time triggers when due, price triggers when the EA reports hedge_fired). Why: no cron needed.
- AI analysis runs in analyzeMarket (src/lib/ai.functions.ts) via src/lib/analysis.server.ts: reuses a shared analysis of the same symbol/timeframe within CACHE_MINUTES, else calls Gemini (model name only in GEMINI_MODEL, src/lib/signal-guard.ts) with no Lovable AI fallback; signal-guard turns weak signals, stale or missing prices or rule-breaking levels into a recorded no-trade (a calendar outage only warns; the last good calendar is cached in memory and in app_settings key calendar_cache). Why: minimise AI cost and keep trade gating in code.
- Admin CRUD pages reuse src/components/admin/AdminCrud.tsx. Why: one consistent table/edit UI.
- Live prices, candles, news and the economic calendar come from free public sources via src/lib/market.server.ts (Yahoo chart API keyed by instruments.yahoo_symbol, RSS feeds, ForexFactory JSON) and also feed the AI analysis prompt. Why: no paid data keys needed.
- UI text is translated with useT() from src/lib/i18n.tsx: the exact English string is the key, Arabic lives in src/i18n/ar-*.ts and falls back to English; language is saved in the browser and sets html dir=rtl. Why: one source of copy, no key bookkeeping.
- Auto-Pilot: a scheduled job (every 15 min) calls POST /api/public/autopilot/run (cron-secret auth); it reuses shared analyses via src/lib/analysis.server.ts, applies the pure rules in src/lib/autopilot.ts, and queues open_trade commands (payload.autopilot=true) for accounts with auto_trading on. Why: trading runs 24/7 without a browser open. Runs every 10 min; SINGLE_AI_CALL (demo challenge) skips the debate to save credits; real trades use REAL_SECOND_CHECK (verifyTrade on approved trades only, skipped when the daily AI budget is used up); no new real trades or analysis in the QUIET_START_UTC–QUIET_END_UTC thin-liquidity window; src/lib/autopilot.ts holds the confidence floor and same-symbol stacking limits.
- AI Brain & Whale Radar run inside each Auto-Pilot cycle (src/lib/brain.server.ts): one Gemini lesson per closed trade, rules merged in learned_rules, Monday weekly review, CFTC COT refreshed daily; both feed the runAI prompt. Why: no extra cron, learning is cheap and automatic. Every analysis with levels (taken or skipped) is graded later against broker candles (src/lib/hindsight.ts) and the per-reason stats feed the prompt.
- New sign-ups get profiles.approval_status='pending' (first user auto-approved); public.is_approved() gates the _authenticated layout (→ /pending) and restrictive RLS on trading tables; only admins can change approval (trigger guard). Why: no one trades before the owner approves them.
- Public marketing pages share src/components/site/SiteChrome.tsx (header, footer, sections); brand logos live as asset pointers in src/assets/logos and render through BrandLogo. Why: one look and one logo source.
- Gemini only proposes; src/lib/risk-engine.ts (pure, tested) can veto every Auto-Pilot trade, and each verdict is written to decision_log. Analysis prefers fresh broker candles the EA sends (broker_candles/broker_quotes) and falls back to Yahoo. Learned rules feed the prompt only once status='approved'; rules merge by topic (ruleTheme/consolidate in src/lib/brain.ts) because the AI rewords each lesson, and the last trade lessons are always in the prompt. Why: decisions must be explainable and measurable.
- The free demo challenge is a multi-asset paper simulator (sim_challenges/sim_trades/sim_events/sim_decisions; pure specs, scanner, supervisor and fills in src/lib/challenge.ts; cycle in src/lib/sim-run.server.ts run by the Auto-Pilot cron with a per-challenge lock). Order: code scanner + Gemini proposal → code tool evidence (src/lib/evidence.ts) + one Gemini bull/bear/manager debate + code checklist → deterministic supervisor veto → fill; closed trades get a process-vs-outcome review (sim_reviews). sim_challenges.use_evidence=false rolls back to the plain second-opinion path. It never writes trade_commands or touches trading_accounts; users can only insert a row and change status via column grants. Why: demo money must be fully separated from real execution and every veto must be explainable.
- Every Gemini call first reserves a slot via takeAiCall() (src/lib/ai-budget.server.ts → public.take_ai_call, cap DAILY_GEMINI_CALLS in signal-guard.ts); over the cap the call is skipped. Why: keep the user's prepaid Gemini credit lasting the month.
